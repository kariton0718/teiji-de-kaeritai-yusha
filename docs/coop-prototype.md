# 2人協力プレイ試作 v1

## 範囲
1人用を保持し、タイトルに「2人で遊ぶ（協力プレイ試作）」を追加。coop.htmlは独立した協力モード。1フロア、2ウェーブ（28＋40体）、魔王リーダー、2人で退勤ゲートまで。全6階・裏ボス・助っ人の移植はまだ行わない。

## 操作
1. ホストが必殺技を選び「部屋を作る」。
2. 表示された招待URLを友達へ送る（コピーまたは共有）。
3. 参加者も必殺技を選び「この部屋に参加する」。
4. 両者が「準備OK」、ホストが「2人で出発」。
5. 画面をドラッグ／WASD・方向キーで移動、自動攻撃、K/Iまたは右下ボタンで必殺。
6. 各ウェーブ後、各自で斬撃・一斉返信・シュレッダーから強化。全員が選ぶまで時計停止。
7. 気力0の仲間に54px以内かつ遮蔽物なしで3秒寄り添うと気力40・無敵2秒で復活。2人とも倒れると失敗。
8. ボス撃破後、2人とも生存して右上のゲートへ。時間制限4分。

5必殺技を協力用に実装。吸引とビームの組み合わせ、別々の気力・ゲージ・強化。味方への攻撃判定なし。選択画面・PCキー・ステージ全体のタッチ移動・必殺ボタンを用意。音は協力画面上部でON、既存のBGM・効果音クラスを再利用（本試作では戦闘イベント効果音は未接続）。

## 通信
PeerJS 1.5.5、PeerJS Cloudで接続仲介、WebRTC DataChannelでゲーム情報を交換。カメラ・マイク不要。部屋IDと128bitの招待鍵をURLフラグメントに格納。鍵・プロトコルが一致する参加者1人だけを受け付ける。
ホストのみ30Hzで戦闘を計算。参加者は入力と強化選択だけを送信、状態やダメージを上書きできない。状態を約15Hzで配信、参加側は描画だけ補間。ゲーム情報以外の個人情報を収集しない。ホスト自身の改造・不正を防止する競技用の方式ではない。
敵38体・弾90発・演出65個上限。入力に数値検証、範囲制限、連番検証。0.4秒入力が届かなければ移動停止。6秒応答なし、接続20秒超、送信待ち128KB超で終了表示。画面非表示・離脱で接続を終了。途中再接続・ホスト移譲は非対応。結果が確定した後の相手退出で結果を上書きしない。

### 接続の制約
無料の公開シグナリングに依存する試作用構成。STUNはstun.l.google.com:19302。TURN中継は未設定。一部の携帯回線・会社Wi-Fi等では直接接続できないため、商用・高可用性向けとはしない。必要なら次段階で認証付きTURNと専用シグナリングを設定する（アカウント・課金未実施）。
公式資料:
- https://peerjs.com/client/getting-started
- https://peerjs.com/server/cloud

## 検証
- 既存機能66件、協力ユニット・通信模擬14件、協力通し3件＝計83件成功（別実行を含む）。
- 模擬Peer間の招待→準備→開始→入力→各自強化→結果共有、3人目・招待鍵不一致の拒否、切断、送信詰まりを検証。実WebRTCの検証ではない。
- 入力のみの自動プレイ3構成でボスと退勤まで成功：本日は退勤します＋定時ラッシュ36.23秒、ブラックホール＋キャノン36.37秒、本日は退勤します＋分身38.67秒。自動操作の速度は人間の所要時間や難易度評価を意味しない。
- 画面描画はNodeのCanvasモックで有限座標確認のみ。
- ブラウザー操作ツールで http://127.0.0.1:8181/coop.html を開いたがERR_BLOCKED_BY_CLIENT。ブラウザーでのレイアウト、2端末の実WebRTC通信、スマホ操作、音の聴感は未確認。
- 旧1人用の自動操縦通しテスト2件は既知の難易度調整後の失敗があり、今回対象外。
